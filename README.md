# Dia Smart Autofill

Dia / Chromium 向けの Manifest V3 拡張機能。既知の情報を端末内に保存し、フォームの空欄への入力を支援します。

## 公開版について

このリポジトリは個人・会社固有の設定を取り除いたソースのサンプルです。実際のプロフィール、APIキー、カード情報、勤務記録、Obsidianのノート、端末のパス、社内の案件名やフォームURLは含みません。以前の入力例を除去するため、0.8.0で公開履歴を新しいルートコミットへ置き換えています。取得済みの旧コピーやキャッシュを回収できるものではありません。

`work@example.test` と `reports.example.test` は架空の設定です。日報・週報のサイト連携は汎用対応ではなく、下記の専用アダプターを使用するフォームに合わせてレビュー・調整する必要があります。公開版をそのまま読み込んでも実際の会社フォームには入力しません。

- `daily-report-company.js`：会社設定のサンプルとDailyフォルダの参照。
- `daily-report-adapter.js` / `content.js`：日報の接続先制限・フォーム構造。
- `weekly-report-adapter.js` / `content.js`：週報のタイトル・質問欄・アカウント確認。
- `daily-report.html`：接続先の表示。

## 主な機能

- 一枚の情報メモ（`項目名：内容`）から、登録済みの情報をJevが選択。任意の独自項目を追加できます。
- 氏名、ふりがな、連絡先、住所などの複数プロフィール。
- ラベル、属性、autocompleteから項目を判定。漢字から読みは推測しません。
- 任意のJev判定（AI優先が既定）。TypeSafe APIキーは設定画面で端末内に保存します。
- カード情報はパスワードで暗号化して保存。解除・入力先の確認が必要です。CVVは保存・入力しません。
- Obsidian DailyのTasksから日報・週報のローカル下書きを生成。
- 週報の投稿日は日本時間の本日。対象は前日までの直前7日間です。

## インストール

1. ソースを取得し、Diaの `chrome://extensions` を開きます。
2. デベロッパーモードを有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」でこのフォルダを選びます。
4. 拡張の設定画面で自分のプロフィールを登録します。APIキーはチャットやGitに貼らないでください。

## 一枚の既存情報 → Jev判断（0.8.0）

1. 更新後、拡張機能を再読み込みし、設定画面も開き直します。
2. 「既存情報を、一枚に。」で「既存の登録をメモにコピー」、または空のひな形から入力します。
3. メモを確認して保存し、Jevをオンにして「AI優先」を選びます。
4. 通常のフォームで拡張の「このページを入力」を押します。保存・送信はしません。

```text
氏名：山田 太郎
ふりがな：ヤマダ タロウ
個人メール：person@example.test
会社メール：work@example.test
得意分野：調査、資料作成
自己紹介：Web開発を学んでいます。
```

メモは完全な自由文ではなく、一行に「項目名：内容」を登録します。続きは二文字以上字下げします。項目名はJevへ送られるため、名前や機密事項を項目名に含めないでください。内容は送信せず、Jevが選んだ登録キーを端末内で解決します。登録されていない回答は生成しません。

- メモを有効にするとメモだけが入力元になります。空にすれば入力しません。従来の項目は残り、メモをオフにすれば再利用できます。
- APIエラー時のみ、一意かつ高一致の候補に限定して従来判定を使います。低確信度や「該当なし」は埋めません。
- 会社用/個人用、カナ、入力型、文字数、既存値・入力途中の変更を保護します。漢字から読みは推測しません。
- 手動実行は最大100欄、20欄ずつ最大5呼び出し。自動実行はキャッシュのみで、新しい有料通信をしません。項目名や型の変更で再判定し、内容だけの変更は端末内で反映します。
- 日報・週報は専用の確認フローのままです。カードや認証情報をメモへ混ぜません。

設計は [PROFILE_SHEET_DESIGN.md](PROFILE_SHEET_DESIGN.md)。Jevの [Choice API](https://docs.typesafe.ai/api) を利用します。

## テスト

Node.js の標準テスト機能を使用します。追加パッケージは不要です。

```sh
node --test tests/*.test.js
python3 -m http.server 8766 --bind 127.0.0.1
```

`http://127.0.0.1:8766/demo/test-form.html` で通常入力を、`http://127.0.0.1:8766/daily-report.html?demo=1` で架空の日報を試せます。テストデータはサンプルであり、実際の業務記録ではありません。

`http://127.0.0.1:8766/demo/profile-sheet-preview.html` は架空データの設定UIです。実際の拡張の保存情報やAPIへアクセスしません。

0.8.0は75件の自動テスト成功。設定画面は架空データで表示・コピー・編集・切り替え、コンソールのエラーなしを確認。保存は模擬テストのみ。新しい動的候補による実Jev呼び出し、本番プロフィールの変更、本番フォームへの入力・保存・送信はこの検証では実施していません。

CLIの限定Daily読み取りを使う場合は、自分のVaultパスを環境変数で指定します。コードやGitへ実際のパスを書き込まないでください。

```sh
OBSIDIAN_VAULT="/path/to/your/vault" node scripts/daily-report-export.js 2026-10-08
```

生成したJSONには作業候補が含まれるため、Gitへ追加しないでください。

## 安全上の境界

- サイトの保存・送信・決済ボタンは押しません。既存の入力値は上書きしません。
- Google Formsは入力だけでGoogleへ下書きを自動保存する場合があります。回答を送信しないことと、クラウドに保存されないことは異なります。入力前に本人の了承が必要です。
- Dailyは本人が選んだ読み取り専用のフォルダから、対象日のTasksだけを抽出します。Notes、未完了・中止・私用タスクは業務記録にしません。
- 勤務予定を実績にせず、休憩・案件別時間・成果を推測しません。本人の確認が必要です。
- Google Calendarの継続認証・自動取得は未実装です。Calendar IDを記憶しても認証は完了しません。
- Jevへ送るのは限定した入力欄の説明・属性と登録項目の名前・型・キーです。プロフィールの内容、ノートやカード情報は送りません。ラベル等に埋め込まれた個人情報を完全に検出できる保証はありません。
- 暗号化は端末や拡張機能の侵害まで防ぐものではありません。
- 自動テストは模擬環境の検証です。利用先フォームのDOMや入力反映は、保存・送信せずに個別確認してください。

日報・週報用のサンプル設定を自分用に変更するときも、個人情報や社内情報を公開リポジトリへコミットしないでください。
